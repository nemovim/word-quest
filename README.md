# word-quest

영어 단어와 예문을 학습하고 복습하는 SvelteKit 애플리케이션입니다.

## game 브랜치 던전 테마

기존 학습 기능 위에 던전 진행, 자원, 장비 강화를 더합니다. 홈의 어휘 수준·주간 변화·학습 통계·앱 설치와 기존 퀴즈의 난이도·활용도·AI 질문·발음·복습 단계·신고·학습 방향을 유지합니다.

- `/quiz`의 기존 출제·채점·복습 로직을 그대로 사용합니다. 체력이 남아 있는 동안 계속 학습하며, 기존 새 단어 12시간 40개 제한과 묶음 완료 화면은 사용하지 않습니다. 내부적으로 9개씩 가져오며 복습할 단어가 있으면 기한이 오래된 순서로 최대 9개를 출제하고 남은 자리를 채우지 않습니다. 복습할 단어가 없으면 새 단어를 출제합니다. 같은 복습 기한에서는 무작위로 출제합니다. 새 단어는 가능한 한 쉬움·현재·어려움 난이도를 균등하게 배분합니다. 최단 복습은 1분이며 클라이언트의 즉시 재출제 큐는 없습니다.
- 몬스터 체력은 문제 이동·새로고침 후에도 유지됩니다. 일반 몬스터는 슬라임·버섯·박쥐·골렘 4종을 무작위로 만나며 Lv.10에서 일반 HP 100, 보스 HP 400이며 레벨이 오르면 최대 체력이 증가합니다. 공격력은 10부터 시작하며 모든 몬스터에 동일하게 적용합니다. 기존 무기는 이전 공격력을 그대로 이어받습니다.
- 연속 정답 2회부터 연계가 발동해 연속 횟수 × 연계율만큼 보너스 피해(최소 1)를 줍니다. 오답이나 넘기기로 연계가 초기화되며 보너스 피해는 공격력의 50%까지입니다. 연계 타격에는 추가 파티클과 보너스 피해 안내가 표시됩니다.
- 플레이어 체력은 100. 오답마다 일반 몬스터는 `floor(단어 난이도 × 3)`, 보스는 `floor(단어 난이도 × 6)` 피해를 받고, 0이면 탐험 종료 후 대시보드로 돌아갑니다. 살아 있는 탐험의 체력은 재접속해도 유지되며 종료 후 재입장하면 새 탐험을 시작합니다. 스킵은 몬스터를 `floor(단어 난이도 × 5)`만큼 회복시킵니다(최대 체력 제한). 5회 오답이면 자동 패스되어 몬스터가 회복합니다. 마지막 오답으로 사망한 경우 탐험을 종료합니다. 오답의 AI 질문·재생성 버튼은 임시로 숨기며 기능은 보존합니다. 전투 요청 ID로 중복 피해·보상을 방지합니다.
- 일반 몬스터 처치 시 종별 자원을 무작위 지급합니다: 슬라임은 골드 5~~10, 버섯은 철 3~~6, 박쥐는 은 1~~3, 골렘은 25% 확률로 강화석 1개입니다. 일반 처치의 보물상자 확률은 5%이며, 보스 처치에서는 보물상자를 확정으로 얻습니다. 상자는 계정에 보관되며 클릭하면 흔들림·빛·뚜껑 열림 후 자원이 차례로 드러납니다. 개봉 요청에서 서버가 추첨하며 상자 소비와 지급을 원자적으로 저장합니다. 재요청은 같은 결과를 반환하고 추가 지급하지 않습니다.
- 보스·일반 상자는 내용물 규칙이 같습니다. 레벨 배수를 적용한 골드 기본량에 30%를 더해 지급하며, 철은 증가한 골드 5개당, 은은 증가한 골드 20개당 비율로 지급합니다. 강화석은 기존 골드 기본량 기준 30개당 기대 1개 방식으로 확률 지급하므로 골드·철·은 증가의 영향을 받지 않습니다. 파편의 자원 획득 강화는 상자 보상에 적용됩니다.
- 상자 개봉은 무료이며 공개 순서는 골드 → 철 → 은 → 강화석입니다.
- 골드는 무기와 방어구가 공유하는 성공률을 +2~~6%p 충전합니다(최대 100%). 성공하면 철 강화는 공격력을 +1~~4 또는 최대 체력을 +2~~6, 은 강화는 명중 골드 또는 처치 회복을 +1~~3, 강화석 강화는 연계율 또는 방어력을 +0.5~~1.5%p 올립니다. 각 범위에서 균등하게 뽑으며 연계율은 최대 15%, 방어력은 최대 50%입니다.
- 기본 성공률은 `floor(사용자 단어 레벨 × 10)%`입니다(최대 100%). 레벨 변동 시 골드로 충전한 추가 확률은 유지합니다. 강화 비용은 항목별 성공 횟수에 따라 증가하며, 최대 체력은 처음에 철 1개를 소모합니다.
- 어휘 레벨은 1에서 시작하며 학습 결과에 따라 0까지 내려갈 수 있습니다. 성공 강화 한도는 어휘 레벨 ×10의 내림값과 환생 횟수 + 10 중 작은 값입니다. 환생하려면 어휘 레벨 ×10의 내림값이 환생 횟수 + 10 이상이고 성공 강화도 그 횟수에 도달해야 합니다. 따라서 첫 환생은 레벨 1.0과 성공 강화 10회부터 가능하며, 레벨 1.3에서 환생 0회라면 10회 강화 후 환생을 거쳐 최대 13회까지 해금할 수 있습니다. 4번째 환생 이후에는 레벨 1.4가 되어야 다음 환생이 가능합니다. 성공률 충전은 횟수에 포함하지 않습니다. 환생은 골드 5,000·철 300·은 100·강화석 10개를 소모하며, 다음 환생 횟수만큼 비용이 선형으로 증가합니다.
- 어휘 레벨은 최근에 답한 단어 최대 500개의 난이도와 복습 단계별 숙련도(0·20·50·70·80·85·88·90%)로 추정합니다. 같은 난이도에서 숙련도 80%를 해당 수준의 기준으로 삼으며, 초반에도 새 단어를 맞히면 복습 주기를 기다리지 않고 반영합니다. 새 문제에는 현재 수준보다 어려운 단어도 섞습니다.
- 환생하면 자원·장비 강화·보물상자·탐험 진행을 초기화하고 기본 능력치와 어휘 레벨을 유지합니다. 첫 환생은 기억의 파편 1개, 이후에는 환생 횟수만큼 파편을 지급합니다. 파편은 보물상자에서 선택한 자원의 획득량을 0.5~1.5%p 올리는 데 사용하며, 선택 자원별 비용은 1개부터 단계마다 1개씩 증가합니다. 획득량 강화와 파편은 환생 후에도 유지되고, 상자의 해당 자원 기본 수량에 획득률을 곱해 적용합니다. 정수 지급 시 소수점은 확률적으로 반영하며 획득 보너스에는 상한이 없습니다. 전투·던전 보상은 이 강화의 영향을 받지 않습니다.
- 시도할 때 재료를 소모합니다. 실패하면 능력치와 충전된 성공률은 유지되며 실패 보정은 없습니다. 무기나 방어구 강화에 성공하면 공통 성공률은 기본값으로 돌아갑니다. 방어력은 오답과 패스 피해를 줄이고, 처치 회복은 몬스터를 쓰러뜨렸을 때 최대 체력까지 회복합니다.
- 기존 RPG 실험의 보유 자원과 무기는 유지됩니다. 기존 별도 출제 화면을 제거하고 던전 진행은 원래 학습 화면에서 새로 시작합니다. 상태 버전과 원자적 갱신으로 중복 보상을 방지합니다.
- 학습 화면의 명중·보상 연출, 선택형 효과음과 움직임 줄이기 설정을 지원합니다.

`npm run dev` 후 홈에서 던전 학습으로 이동합니다.

## 실행 준비

Node.js 24를 사용합니다. 저장소의 `.nvmrc`와 같은 버전을 선택한 뒤 의존성을 설치합니다.

```sh
npm install
```

`.env.example`을 `.env`로 복사하고 실제 값을 입력합니다. `MONGO_URI`, Google OAuth 설정,
`AUTH_SECRET`, `OPENROUTER_API_KEY`는 애플리케이션의 핵심 기능에 필요합니다. 단어 점수 평가에
사용할 OpenRouter 결정 모델은 `OPENROUTER_DECISION_MODEL`로 지정합니다.
확신도가 부족한 점수는 보류합니다. 기본 기준은 점수 확신도 0.35 이상과 번역 유효·무효
판정 확률 0.8 이상이며 각각 `VOCA_SCORE_MIN_CONFIDENCE`, `VOCA_VALIDITY_MIN_CONFIDENCE`로
조정할 수 있습니다. 점수 확신도 기준 0.35는 정확도 검증이 아직 필요한 임시값입니다.
번역이 확실히 유효하지 않으면 다른 점수의 확신도와 관계없이 활용도 0으로 제외합니다.
`.env`의 `OPENROUTER_API_KEY`는 채점·예문 생성·검토에 공통으로 쓰며,
`OPENROUTER_MODEL`은 예문 생성용 텍스트 모델,
`OPENROUTER_DECISION_MODEL`은 단어 채점에 쓰는 결정 모델입니다.
기존 다른 텍스트 AI 기능도 `OPENROUTER_MODEL`을 사용합니다.

`ADMIN_EMAILS`에는 관리자 Google 계정 이메일을 쉼표로 구분해 입력합니다. 허용된 계정으로
로그인하면 상단에 `신고 관리` 메뉴가 나타납니다. 신고의 AI 제안 생성과 최종 반영은 이
관리자 화면에서만 수행합니다.

## PWA와 오프라인 화면

SvelteKit 내장 서비스 워커를 사용하며 별도 PWA 런타임 플러그인은 필요하지 않습니다.
`static/offline.html`, `offline.css`, `offline.js`는 빌드 자산과 함께 미리 캐시됩니다.
페이지 이동은 네트워크를 먼저 사용하고, 연결 실패 시 오프라인 메모 화면을 표시합니다.
다시 연결하기는 원래 요청한 URL을 다시 열며, 연결 상태가 바뀌면 안내 문구를 갱신합니다.
사용자별 페이지와 API 응답은 캐시하지 않습니다.

프로덕션 빌드를 한 번 온라인으로 방문해 서비스 워커가 활성화된 뒤,
브라우저 개발자 도구에서 Offline으로 전환하고 새로고침 및 앱 내 메뉴 이동을 확인합니다.
디자인만 확인하려면 `/offline.html`을 열면 됩니다.

## 단어 점수 관리

점수 작업은 등록된 모든 단어(사용자 추가 단어 포함)를 대상으로 합니다. `--limit`은 보류나
실패를 포함해 **선택한 단어 수**의 상한이며, 생략하면 해당 모드의 전체 대상을 처리합니다.
`all` 모드에서 제한을 걸어 재실행하면 처음부터 다시 선택하므로 자동 이어받기는 하지 않습니다.
결정 모델이 확신하지 못한 단어는 기존 점수를 보존하면서 보류 상태로 표시하고 실행 보고서 옆의
`.deferred.jsonl` 파일에 판정 확률, 점수, 확신도와 모델이 반환한 단계별 확률 분포를 기록합니다.
확률 분포의 단계 번호는 API 원본 그대로 0부터 시작합니다. 다음 실행에서 다시 평가할 수 있습니다.
아래 명령은 PowerShell의 `npm.ps1`이 옵션을 소비할 수 있어 `npm.cmd`를 사용합니다.

| 모드      | 역할                                                           |
| --------- | -------------------------------------------------------------- |
| `missing` | 난이도나 활용도가 없거나 점수 평가가 보류된 단어를 평가합니다. |
| `zero`    | 첫 평가에서 `utilityScore` 0을 받은 단어를 한 번 재검사합니다. |
| `all`     | 모든 등록 단어의 기존 점수를 다시 평가합니다.                  |

```sh
npm.cmd run vocas:score -- missing --limit=10
npm.cmd run vocas:score -- all --limit=100
npm.cmd run vocas:score -- all
```

## 예문 생성

예문 생성은 난이도와 활용도가 모두 평가된 등록 단어를 **활용도가 높은 순서**로 처리합니다.
범위는 `missing`(예문 없음), `existing`(예문 있음), `all`(모두) 중 하나를 필수로 선택합니다.
활용도 2.0 미만으로 평가된 단어와 평가가 보류된 단어는 예문 생성과 학습 대상에서 제외됩니다.
`--limit`은 선택한 단어 수의 상한이며, 기존 예문은 보존하고 중복되지 않은 예문을 추가합니다.
`all`·`existing` 모드는 재실행 시 다시 높은 활용도부터 시작합니다. `missing` 모드에서도
보류되거나 예문 저장에 실패한 단어는 다음 실행의 후보로 남습니다.
첫 요청에서는 예문과 빈칸만 생성합니다. 형식 검사 후 `OPENROUTER_MODEL`이 최대 5개씩 묶어
문장의 자연스러움, 번역과 양쪽 빈칸의 의미 일치를 검토하고 한글 발음을 생성합니다.
영어 빈칸은 로컬 CMUdict에서 모든 단어의 발음 후보를 찾습니다. 사전에 없거나 지원하지 않는
문자가 포함된 답안은 저장하지 않고 보류합니다. `OPENROUTER_MODEL`이 문맥에 맞는 ARPAbet
발음을 고르고 그 발음의 한글 표기를 함께 생성합니다. 한글 발음은 별도의 결정 모델 검토 없이
생성 결과를 사용합니다. 사전 누락이나 검토·발음 선택 불확실에 따른 보류는 개별 예문에 적용되며, 이미 등록된 단어의 점수와
다른 예문은 유지됩니다. 새 단어 추가에서는 생성한 예문이 모두 보류되면 단어 등록을 마칠 수 없습니다.
사전 누락 보류 항목은 재검토하거나 직접 승인할 때도 사전 확인을 통과해야 합니다.
CMUdict는 미국 영어 발음 사전이며, 발음 후보가 있다는 것만으로 문맥에 맞는 선택이 보장되지는 않습니다.
새로 저장되는 영어 예문에는 강세 숫자가 포함된 CMU 원본(`targetPronunciationArpabet`, 단어별
`|` 구분)을 저장하며, IPA는 퀴즈 정답을 보여줄 때 원본에서 변환합니다. CMUdict에는 음절 경계가
없어 IPA의 강세 기호 위치는 음절 시작을 추정한 결과입니다. 기존 예문에 CMU 원본을 자동으로 채우지는
않으며, 원본이 없는 예문은 모든 단어의 CMU 발음 후보가 하나일 때만 조회해 IPA를 표시합니다.
Luna가 판단하지 못한 예문은 관리자 `보류 예문` 화면에 보관합니다. 예문 검토에는 결정 모델을 호출하지 않습니다.
보류 항목만 다시 검토하거나 직접 수정해 승인·제외할 수 있습니다. 일괄 재검토는 한 번에 최대 25개입니다.
아직 저장되지 않은 새 단어의 예문은 해당 단어를 먼저 추가해야 승인할 수 있습니다.
단어 채점은 `OPENROUTER_DECISION_MODEL`을 사용합니다.

```sh
npm.cmd run vocas:examples -- missing --limit=10
npm.cmd run vocas:examples -- existing --limit=10
npm.cmd run vocas:examples -- all --limit=100
npm.cmd run vocas:examples -- missing
```

점수 평가는 OpenRouter 결정 모델 API를, 예문 생성은 OpenRouter 텍스트 모델을 사용하며 API
비용이 발생하고 데이터베이스를 변경합니다. 각각 `.env`의 `OPENROUTER_DECISION_MODEL`과
`OPENROUTER_MODEL`로 모델을 지정합니다. 난이도는 소수 둘째 자리, 활용도는 첫째 자리까지 저장합니다.
실행 기록은 각각 `logs/voca-scoring/`과 `logs/example-generation/`에 저장되며 Git과
Prettier의 검사 대상에서는 제외됩니다.

### 어휘 수준에 따른 몬스터 성장

몬스터 등장 시 `floor(사용자 어휘 수준 × 10)`으로 정수 레벨(Lv.10~100)을 저장합니다. `x = 몬스터 레벨 / 10 - 1`, 성장값 `g = x/2 + x²/18`의 완만한 2차식을 사용합니다. 일반 최대 체력은 `100 + round(2900 × ((레벨 - 10) / 90)^(log(29) / log(9)))`, 보스는 같은 레벨 일반 몬스터의 4배이며, 명중 골드는 기본 1이며 은 강화로 영구 증가합니다. 상자 골드·철은 기본 무작위 수량에 `1 + 0.2g`를 곱한 후 버림합니다. 사용자 어휘 수준은 소수점 둘째 자리까지, 몬스터는 정수로 표시합니다. 전투 중 체력은 고정되며 상자는 처치 당시 레벨을 보존합니다. 기존 전투에 새 최대 체력을 적용할 때는 남은 체력 비율을 유지하고, 기존 소수 레벨 스냅샷은 정수 체계로 변환합니다. 레벨이 없는 기존 몬스터·상자는 Lv.10으로 취급합니다.

## 이름 변경 호환성

새 환경의 기본 DB 이름은 `word-quest`입니다. 기존 `.env`와 데이터 이관 노트북의 `word-note` DB 이름은 기존 학습 데이터를 계속 사용하도록 유지합니다. 복습 서명 식별자와 이전 서비스 워커 캐시 정리용 이름도 호환성을 위해 유지합니다.
