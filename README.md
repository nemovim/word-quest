# word-quest

영어 단어와 예문을 학습하고 복습하는 SvelteKit 애플리케이션입니다.

## game 브랜치 던전 테마

기존 학습 기능 위에 던전 진행, 자원, 장비 강화를 더합니다. 홈의 어휘 수준·주간 변화·학습 통계·앱 설치와 기존 퀴즈의 난이도·활용도·AI 질문·발음·복습 단계·신고·학습 방향을 유지합니다.

- `/quiz`의 기존 출제·채점·복습 로직을 그대로 사용합니다. 체력이 남아 있는 동안 계속 학습하며, 기존 새 단어 12시간 40개 제한과 묶음 완료 화면은 사용하지 않습니다. 내부적으로 5개씩 가져오며 복습 기한이 오래된 순서, 같은 기한이면 무작위로 출제하고 남은 자리를 새 단어로 채웁니다. 최단 복습은 1분이며 클라이언트의 즉시 재출제 큐는 없습니다.
- 몬스터 체력은 문제 이동·새로고침 후에도 유지됩니다. 일반 몬스터는 슬라임·버섯·박쥐·골렘 4종을 무작위로 만나며 기본 HP 120, 새 조우마다 5% 확률로 보스 HP 480. 공격력은 10부터 시작하며 모든 몬스터에 동일하게 적용합니다. 기존 무기는 이전 공격력을 그대로 이어받습니다.
- 정답 공격은 서버에서 무기에 저장된 확률(새 무기 기본 1%, 최대 100%)로 크리티컬을 판정해 강화 포함 공격력의 2배 피해를 줍니다. 실제 피해는 남은 체력까지 적용하며 금빛 타격·큰 피해 숫자·별도 효과음으로 표시합니다.
- 플레이어 체력은 100. 오답마다 일반 몬스터는 `floor(단어 난이도 × 3)`, 보스는 `floor(단어 난이도 × 6)` 피해를 받고, 0이면 탐험 종료 후 대시보드로 돌아갑니다. 살아 있는 탐험의 체력은 재접속해도 유지되며 종료 후 재입장하면 새 탐험을 시작합니다. 스킵은 몬스터를 `floor(단어 난이도 × 5)`만큼 회복시킵니다(최대 체력 제한). 5회 오답이면 자동 패스되어 몬스터가 회복합니다. 마지막 오답으로 사망한 경우 탐험을 종료합니다. 오답의 AI 질문·재생성 버튼은 임시로 숨기며 기능은 보존합니다. 전투 요청 ID로 중복 피해·보상을 방지합니다.
- 처치 시 보물상자가 계정에 저장됩니다. 클릭하면 흔들림·빛·뚜껑 열림 후 자원이 차례로 드러납니다. 개봉 요청에서 서버가 추첨하며 상자 소비와 지급을 원자적으로 저장합니다. 재요청은 같은 결과를 반환하고 추가 지급하지 않습니다.
- 은은 일반 상자에서 `floor(45 + 2g)%` 확률로 1~~2개, 보스 상자에서 2~~4개 확정 지급합니다. 철보다 드물고 강화석보다 흔하며 공개 순서는 골드 → 철 → 은 → 강화석입니다.
- 일반 상자: 25~~50골드, 철 2~~5개(각 균등), 강화석 1개 확률 12%. 보스 상자: 100~~125골드, 철 8~~12개(각 균등), 강화석 1개 80% / 2개 20%. 개봉 비용은 없습니다.
- 강화는 자원별로 분리합니다. 골드: 공통 성공률 +5%p 충전(최대 100%). 은: 성공 시 명중 골드 +1~3. 기본 명중 골드는 1이며 몬스터 레벨과 무관하게 강화한 수입을 지급합니다. 철: 성공 시 공격력 +2~~6. 강화석: 성공 시 치명타 +1~~3%p(최대 100%). 능력치 증가량은 균등 추첨합니다.
- 기본 성공률은 `floor(사용자 단어 레벨 × 10)%`입니다(최대 100%). 레벨 변동 시 골드로 충전한 추가 확률은 유지합니다. 골드 비용은 `floor((20 + 검 강화 단계 × 5) × (1 + (현재 성공률 / 20)²))`, 철은 `2 + 공격력 강화 성공 횟수`, 강화석은 `1 + floor(치명타 강화 성공 횟수 / 5)`. 은 비용은 `2 + floor(수입 강화 성공 횟수 / 3)`입니다. 각 강화는 해당 자원만 소모합니다.
- 시도할 때 재료를 소모합니다. 실패하면 능력치와 충전된 성공률은 유지되며 실패 보정은 없습니다. 공격력·치명타·골드 수입 강화에 성공하면 충전분을 소모하고 공통 성공률은 현재 단어 레벨의 기본값으로 돌아갑니다. 0%에서는 강화를 시도할 수 없습니다. 기존 공격력·치명타는 보존하고 이전 실패 보너스는 적용하지 않습니다.
- 기존 RPG 실험의 보유 자원과 무기는 유지됩니다. 기존 별도 출제 화면을 제거하고 던전 진행은 원래 학습 화면에서 새로 시작합니다. 상태 버전과 원자적 갱신으로 중복 보상을 방지합니다.
- 학습 화면의 명중·보상 연출, 선택형 효과음과 움직임 줄이기 설정을 지원합니다.

`npm run dev` 후 홈에서 던전 학습으로 이동합니다.

## 실행 준비

Node.js 24를 사용합니다. 저장소의 `.nvmrc`와 같은 버전을 선택한 뒤 의존성을 설치합니다.

```sh
npm install
```

`.env.example`을 `.env`로 복사하고 실제 값을 입력합니다. `MONGO_URI`, Google OAuth 설정,
`AUTH_SECRET`, `OPENROUTER_API_KEY`는 애플리케이션의 핵심 기능에 필요합니다.

`ADMIN_EMAILS`에는 관리자 Google 계정 이메일을 쉼표로 구분해 입력합니다. 허용된 계정으로
로그인하면 상단에 `신고 관리` 메뉴가 나타납니다. 신고의 AI 제안 생성과 최종 반영은 이
관리자 화면에서만 수행합니다.

## 개발 명령

| 명령                   | 역할                                                      |
| ---------------------- | --------------------------------------------------------- |
| `npm run dev`          | 개발 서버를 실행합니다.                                   |
| `npm run build`        | 배포용 빌드를 생성합니다.                                 |
| `npm run preview`      | 생성한 배포용 빌드를 로컬에서 확인합니다.                 |
| `npm run check`        | Svelte 및 TypeScript 진단을 실행합니다.                   |
| `npm run fix`          | 전체 파일을 포맷하고 소스, 테스트, 스크립트를 린트합니다. |
| `npm test`             | 전체 테스트를 한 번 실행합니다.                           |
| `npm run test:watch`   | 변경을 감시하며 테스트를 반복 실행합니다.                 |
| `npm run pwa:generate` | `static/favicon.svg`에서 PWA 아이콘을 다시 생성합니다.    |

`prepare`는 `npm install` 뒤 Git 훅을 설치하는 npm 생명주기 명령입니다. 커밋 훅은 변경 파일의
포맷과 린트, `npm run check`를 확인합니다. `package.json`이나 `package-lock.json`이 변경된
커밋에서는 `npm run lockfile:check`도 자동으로 실행해 잠금 파일의 일관성을 검증합니다.

## PWA와 오프라인 화면

SvelteKit 내장 서비스 워커를 사용하며 별도 PWA 런타임 플러그인은 필요하지 않습니다.
`static/offline.html`, `offline.css`, `offline.js`는 빌드 자산과 함께 미리 캐시됩니다.
페이지 이동은 네트워크를 먼저 사용하고, 연결 실패 시 오프라인 메모 화면을 표시합니다.
다시 연결하기는 원래 요청한 URL을 다시 열며, 연결 상태가 바뀌면 안내 문구를 갱신합니다.
사용자별 페이지와 API 응답은 캐시하지 않습니다.

프로덕션 빌드를 한 번 온라인으로 방문해 서비스 워커가 활성화된 뒤,
브라우저 개발자 도구에서 Offline으로 전환하고 새로고침 및 앱 내 메뉴 이동을 확인합니다.
디자인만 확인하려면 `/offline.html`을 열면 됩니다.

## 단어 점수 관리

점수 작업은 목적을 나타내는 모드 하나만 받습니다. 모든 모드는 대상 전체를 100개 표제어씩
처리하고 결과를 데이터베이스에 저장합니다.

| 모드      | 역할                                                           |
| --------- | -------------------------------------------------------------- |
| `missing` | 점수가 없는 사전 단어만 평가합니다.                            |
| `zero`    | 첫 평가에서 `utilityScore` 0을 받은 단어를 한 번 재검사합니다. |
| `all`     | 기존 평가 시각과 관계없이 모든 사전 단어를 다시 평가합니다.    |

```sh
npm run vocas:score -- missing
npm run vocas:score -- zero
npm run vocas:score -- all
```

## 예문 생성

예문 생성은 `utilityScore` 하나만 받습니다. 지정한 점수의 사전 단어 중 예문이 없는 대상을
10개씩 모두 처리하고, 검증을 통과한 예문을 데이터베이스에 저장합니다. 점수는 1부터 5까지
지정할 수 있습니다.

```sh
npm run examples:generate -- 4
```

점수 평가와 예문 생성은 OpenRouter API 비용이 발생하고 데이터베이스를 변경합니다. 웹의
AI 기능을 포함한 모든 OpenRouter 작업은 `.env`의 `OPENROUTER_MODEL` 하나를 사용합니다.
실행 기록은 각각 `logs/voca-scoring/`과 `logs/example-generation/`에 저장되며 Git과
Prettier의 검사 대상에서는 제외됩니다.

### 어휘 수준에 따른 몬스터 성장

몬스터 등장 시 `floor(사용자 어휘 수준 × 10)`으로 정수 레벨(Lv.10~100)을 저장합니다. `x = 몬스터 레벨 / 10 - 1`, 성장값 `g = x/2 + x²/18`의 완만한 2차식을 사용합니다. 일반 체력은 `floor(1.5 × floor(80 + 12g))`, 보스는 `floor(1.5 × floor(4 × (80 + 12g)))`, 명중 골드는 기본 1이며 은 강화로 영구 증가합니다. 상자 골드·철은 기본 무작위 수량에 `1 + 0.2g`를 곱한 후 버림합니다. 일반 강화석 확률은 `floor(12 + 2g)%`, 보스 강화석 2개 확률은 `floor(20 + 3g)%`입니다. 사용자 어휘 수준은 소수점 둘째 자리까지, 몬스터는 정수로 표시합니다. 전투 중 체력은 고정되며 상자는 처치 당시 레벨을 보존합니다. 기존 소수 레벨 스냅샷은 정수 체계로 한 번 변환하며 상자는 유지하며 기존 몬스터 최대·현재 체력을 각각 1.5배 버림해 한 번 상향합니다. 레벨이 없는 기존 몬스터·상자는 Lv.10으로 취급합니다.

## 이름 변경 호환성

새 환경의 기본 DB 이름은 `word-quest`입니다. 기존 `.env`와 데이터 이관 노트북의 `word-note` DB 이름은 기존 학습 데이터를 계속 사용하도록 유지합니다. 복습 서명 식별자와 이전 서비스 워커 캐시 정리용 이름도 호환성을 위해 유지합니다.
